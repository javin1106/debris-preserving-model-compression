# Phase 4 — Pruning, INT8 quantization, benchmarking (settings G, H)

> Hardware note (2026-10-14): "RTX 3050" / "3050" below means the laptop's RTX 4060 Laptop GPU (8 GB).
> See `docs/STATUS.md` → Corrections.

## Goal
Compare the other two compression routes against width-scaled students, and measure every model's
real size, speed and memory on low-power hardware.

## Tasks

### 4.1 Structured pruning — `src/debriskd/prune.py` (setting G)
- Library: Torch-Pruning (https://github.com/VainF/Torch-Pruning). Ask the user before installing; pin the version.
- Importance: L1 magnitude (`MagnitudeImportance(p=1)`); structured channel pruning of the chosen teacher.
- Pruning ratios: 25% and 50% of channels. Exclude the final classifier conv and the input stem's in-channels.
- Use the dependency graph so depthwise convs, the attention module and the decoder concat stay consistent.
  If a layer type breaks the graph, add it to `ignored_layers` and document it.
- Verify after pruning: forward pass works; record parameter count.
- Fine-tune with the official recipe for a fixed number of epochs (propose a number to the user, e.g. 20),
  seeds {0, 1, 2}; model selection on validation as in `train.py`.
- Optional (ask first): prune the best Phase 3 student.

### 4.2 INT8 quantization — `src/debriskd/quantize.py` (setting H)
- Models: the teacher, and the best student from Phase 3 (best validation debris F1 at the smallest width that keeps it).
- Export to ONNX on CPU (FP32), fixed input 1×11×240×240. Check ONNX output vs PyTorch output (max abs diff, and argmax agreement ≥ 99.9%).
  If an mmcv layer blocks export, document it and try the closest opset that works; if export is impossible,
  fall back to PyTorch post-training static quantization and say so.
- ONNX Runtime static quantization (`quantize_static`, QDQ format, per-channel weights) with a calibration reader
  over ~200 **training** patches (fixed random selection, seed logged).
- Evaluate INT8 models on val and test with the same metric code (labelled pixels only).
- If debris F1 drops by more than 2 points vs FP32: report it; propose QAT to the user rather than doing it silently.

### 4.3 Benchmarking — `src/debriskd/benchmark.py`
For every model (teacher, students at all widths, best KD student per width, pruned models, INT8 models):
- Parameters (count), FLOPs at 1×11×240×240 (fvcore; same input for all).
- File size on disk: FP32 state dict, ONNX FP32, ONNX INT8 (where applicable).
- Latency, batch 1: 50 warm-up + 200 timed runs; report median and p90 in ms.
  - RTX 3050 (PyTorch FP32, `torch.cuda.synchronize()` around timing)
  - CPU with 8 threads and with 1 thread (PyTorch FP32 and ONNX Runtime FP32/INT8)
- Peak memory: GPU `torch.cuda.max_memory_allocated()`; CPU peak RSS during inference.
- Record hardware, driver, library versions and thread settings in `env.json`.
- **Run only on the laptop (RTX 3050 / CPU). Never benchmark latency on the H100.**
- Close other heavy programs; run each benchmark 3 times and keep the median of medians.

### 4.4 Summary
- `results/efficiency.csv`: model, setting, width/ratio, precision, params, FLOPs, sizes, latencies, peak memory,
  debris F1 (val/test, mean ± sd where seeds exist).
- `results/fig_accuracy_vs_latency.png`, `results/fig_accuracy_vs_size.png`.
